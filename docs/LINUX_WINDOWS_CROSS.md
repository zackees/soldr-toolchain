## Compiler-rt and intrinsic headers

The Linux-hosted [compiler-rt recipe](../recipes/compiler-rt-windows-x64/README.md)
repackages matching LLVM 21.1.5 AMD64 builtins. Its `__udivti3` definition resolves
unsigned 128-bit division generated by clang for the original C libobs reference.
Consumers must provision this resource overlay at
`lib/clang/21/lib/windows/clang_rt.builtins-x86_64.lib` and select/link compiler-rt
builtins for MSVC targets. Do not substitute Rust builtins for the original C
reference or change OBS source to work around the missing managed library.

The reported SSE failures are a separate, reproduced header precedence bug in
soldr 0.9.53. Its targeted clang wrapper prepends xwin CRT/SDK `-isystem` paths,
so `<intrin.h>` and `<immintrin.h>` resolve to Microsoft's declarations instead
of clang's inline implementations. A Linux C probe covering all **19** reported
SSE intrinsic symbols reproduces all 19 undefined references at `-O2`.
Inserting clang's resource include directory before the first xwin
`-isystem` argument produces an object with **no undefined symbols**. The fix
belongs in soldr's driver ordering. No new SSE shims are needed in this recipe.

The consumer also needs an actual clang-cl driver. Passing `--driver-mode=cl`
through the existing GNU wrapper is insufficient: its injected `-isystem`,
`-L` and `-ivfsoverlay` arguments become ignored options/extra source operands,
ending with `cannot specify '/Fo...' when compiling multiple source files`.
Generate mode-correct include/library/VFS arguments, retain the xwin case
overlay, and qualify both GNU-style clang and clang-cl with CMake on Linux.

## VC runtime closure and licensing

The [local/private runtime recipe](../recipes/vc-runtime-windows-x64/README.md)
extracts ten unmodified AMD64 release DLLs from a pinned official Visual Studio
14.52.37029 manifest payload on Linux. It includes `vcruntime140.dll`,
`vcruntime140_1.dll`, `vcruntime140_threads.dll`, `msvcp140*.dll`, `concrt140.dll`
and `vccorlib140.dll`. No Windows target code runs during packaging.

Public DLL publication is intentionally unavailable. Microsoft's
[redistribution guidance](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files)
limits redistribution to licensed Visual Studio users under the applicable
terms. Its [2026 REDIST list](https://learn.microsoft.com/en-us/visualstudio/releases/2026/redistribution)
permits listed, unmodified components with a program subject to those terms.
The [runtime installation EULA](https://visualstudio.microsoft.com/license-terms/vs2026-ga-visualcpp-v14-redist-runtime/)
provides installation/use rights and restricts publishing/distributing the code.
Those sources do not establish a right for this catalogue to mirror standalone
DLL bundles publicly. Follow the existing Microsoft private-bytes policy and
establish the entitlement and distribution route, or fetch directly from
Microsoft for local use with license acknowledgement.

Use a runtime at least as recent as the MSVC build tools, as required by
[Microsoft's compatibility guidance](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170).
Do not reuse the older 14.44.35211 payload from the legacy VS17 channel for the
installed 14.44.35220 headers. The pinned 14.52 release matches the currently
supported v14 redistributable and exceeds that requirement. Windows 10+/Server
2016+ supply [UCRT as an OS component](https://learn.microsoft.com/en-us/cpp/windows/universal-crt-deployment?view=msvc-170).

## Qualification and publication

Run `uv run --group dev pytest`. Tests cover the exact Linux Forge selection,
version/source pins, signature rejection, architecture and symbol rejection,
safe extraction, license gating and exclusion of debug/foreign runtime DLLs.

Before consumer activation, package the real upstream LLVM archive, prove a
managed Linux clang/lld-link PE DLL containing unsigned 128-bit division links,
and verify no undefined SSE symbols with the corrected header ordering. Inspect
the real CRT DLLs' PE headers/imports and preserve their bytes. These are Linux
package/link proofs; they do not qualify native Windows execution or the full
OBS CTest matrix.

The public builtins dispatch uses the existing workflow and automatically
queues ingest. Review/merge the ingest PR against `assets`, admit the new source
row without removing prior rows, update `multipart-external-entries.v1.json`'s
expected source count on both branches, and run `publish-multipart.yml` through
verified catalogue publication. Keep previously published bytes immutable.
